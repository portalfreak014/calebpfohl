# Content-First Vocabulary Migration

## Status
Planned high-priority foundation work. This migration makes vocabulary data reusable across study, audio, matching, generated quizzes, sentences, fill-in-the-blank exercises, mini exams, and future learning activities.

## Decision
Vocabulary JSON is canonical learning content, not quiz configuration. Activity-specific presentation data—such as a multiple-choice question's displayed choices—must be generated by the activity at runtime rather than stored in each vocabulary record.

## Architecture
The product separates three layers:

1. **Content:** canonical vocabulary records, meanings, linguistic metadata, audio, examples, and tags.
2. **Activity logic:** quiz, matching, cloze, exam, and future modules generate interactions from canonical records.
3. **Learner state:** progress, mastery, and results are recorded against a stable vocabulary ID independently of the activity that produced them.

## Canonical vocabulary record
Each vocabulary item must have a permanent, stable `id`. Array order and visible numbering are not identifiers and may change without changing learner progress, analytics history, matching links, or audio references.

```json
{
  "id": "u6-001",
  "arabic": "يَكْتُبُ",
  "transliteration": "yaktubu",
  "glosses": ["he writes", "he is writing"],
  "partOfSpeech": "verb",
  "unit": 6,
  "chapter": 30,
  "audio": {
    "status": "pending",
    "src": null
  },
  "examples": [],
  "tags": ["core-vocabulary"]
}
```

### Required fields
- `id`: permanent unique identifier, using the unit-prefixed convention such as `u6-001`.
- `arabic`: the canonical Arabic word, phrase, or expression.
- `glosses`: one or more approved English meanings.
- `unit` and `chapter`: content location metadata.

### Recommended fields
- `transliteration`: learner-facing transliteration when appropriate.
- `partOfSpeech`: for filtering and appropriate generated distractors.
- `audio`: audio coverage and asset reference. Start with `status: "pending"` and `src: null` until an approved clip exists.
- `examples`: structured example sentences for future cloze and sentence activities.
- `tags`: reusable category and difficulty metadata.

## Audio contract
Audio is optional per record during rollout. When present, it must reference an approved, licensed clip. The application must gracefully omit or disable playback where `src` is unavailable, and coverage must be trackable through the `status` field.

## Generated quiz behavior
The quiz reads canonical records and generates a question at runtime:

1. Select a target vocabulary record.
2. Select the prompt and answer direction: Arabic-to-English or English-to-Arabic.
3. Use the target record's approved primary gloss as the correct answer.
4. Choose compatible distractors from other records, preferably with the same part of speech and comparable level.
5. Shuffle the displayed choices.
6. Record the result by the target record's stable `id`, not by an array index, display number, or generated-question number.

A generated question may look like this, but is not stored as canonical content:

```js
{
  itemId: "u6-001",
  prompt: "يَكْتُبُ",
  correctAnswer: "he writes",
  choices: ["he writes", "she studies", "they travel", "we understand"]
}
```

## Quiz quality controls
Generated distractors must be reviewed through explicit rules:

- Prefer records with the same `partOfSpeech`.
- Exclude duplicate and near-duplicate glosses.
- Exclude answers that could reasonably be accepted as correct.
- Prefer phrase-to-phrase and word-to-word comparisons where possible.
- Support limited activity-specific overrides only for genuine exceptions.

Example exception metadata:

```json
{
  "id": "u6-001",
  "quiz": {
    "primaryGloss": "he writes",
    "excludedDistractorIds": ["u6-019"]
  }
}
```

## Activity reuse
The same canonical record must be usable by:

- Study cards with Arabic, meaning, transliteration, and playback.
- Matching games using Arabic, gloss, audio, or example-sentence modes.
- Quiz questions generated from approved glosses.
- Fill-in-the-blank exercises based on structured examples.
- Mini practice exams combining recognition, recall, listening, and cloze questions.
- Known-vocabulary and mastery tracking keyed by stable `id`.

## Migration plan
1. Define and validate the canonical record schema and stable-ID convention.
2. Convert Unit 6 and Unit 7 vocabulary to canonical records. Preserve current records as a migration backup until regression testing is complete.
3. Add `audio` objects with `pending` status and null sources, ready for incremental audio coverage.
4. Update quiz logic to derive correct answers and distractors at runtime and to record results by stable ID.
5. Update matching and study views to consume canonical records rather than quiz-specific fields.
6. Add content validation for duplicate IDs, missing required fields, duplicate/ambiguous glosses, invalid audio paths, and invalid unit/chapter metadata.
7. Test quiz, matching, progress persistence, and data loading across both units before removing legacy quiz-specific fields.

## Acceptance criteria
- Vocabulary records contain no pre-authored multiple-choice answer arrays as a requirement of canonical content.
- Every migrated item has a unique, permanent stable ID.
- Quiz questions render successfully from canonical data and generate valid, non-ambiguous choices.
- Existing learner progress is preserved or migrated to stable vocabulary IDs without regression.
- Study and matching experiences continue to work from the shared content model.
- Audio can be added to an individual item without changing quiz or activity data structures.
- Automated or repeatable validation identifies malformed records before release.
